# Episode 1: Installing LAMMPS on EuroHPC

We would like to share series of short tutorials/information with Lammps beginners who would like to practice molecular dynamic simulation on EuroHPC system.

## Installation: Using a prebuilt executable or compiling yourself
LAMMPS (Large-scale Atomic/Molecular Massively Parallel Simulator) uses a tiered release cycle to balance the rapid delivery of new features with the need for long-term stability in research.

| Release type | Frequency | Purpose |
| -------- | -------- | -------- |
| Feature Release | Every 4-6 weeks   | Includes new features, bug fixes, and code refactorings.|
|Stable Releases| About once a year|A "frozen" version that has undergone extensive manual testing and a stabilization period. |
|Bug-fix for Stable Release|Occasional|Periodic bug-fix-only updates to the current Stable version|

The newest update for stable version of Lammps is recommended for beginner to start with and the [Lammps release page on github](https://github.com/lammps/lammps/releases) is always worth to track every a few weeks.

### Prebuilt executables on EuroHPC systems

Lammps is almost installed on every EuroHPC system, but not guarantee it is the newest stable version (or with bug-fix).


| EuroHPC system | User document page about Lammps (installed) |
| -------- | -------- |
| LUMI     | https://docs.csc.fi/apps/lammps/ , https://lumi-supercomputer.github.io/LUMI-EasyBuild-docs/l/LAMMPS/     |
|Discoverer|https://docs.discoverer.bg/lammps.html|
|Vega|https://doc.vega.izum.si/lammps/|
|MareNostrum5|https://www.bsc.es/marenostrum/marenostrum/available-software/lammps|
|Leonardo|https://www.hpc.cineca.it/systems/software/scientific-field/physics/lammps/|

|Karolina|https://docs.it4i.cz/en/docs/software/modules/modules-karolina|

A common step to setup the system installed Lammps for user (different HPC system may different, please refer to the document):

```bash
module load lammps
```
If above command works, you could find where is the lammps executable through
```bash
which lmp
```

LAMMPS uses [a modular Package System](https://docs.lammps.org/Packages.html) to keep the core executable lightweight, while allowing users to include only the specific features (force fields, fixes, or hardware optimizations) they need.
That means the features user need maybe not compiled into the installed Lammps executable. User could use:

  ```bash
  lmp -help | sed -n '/Installed packages:/,/List of individual/p'
  ```
to check the compiling information.
a example output:
```bash
Installed packages:

GRAPHICS KOKKOS KSPACE MANYBODY MOLECULE RIGID

List of individual style options included in this LAMMPS executable
```
For my case, only very few packages are installed. Be noticed that yours could be different from above.
If the HPC center installed Lammps do not contain the function you need, you could either contact the support team to compile a special version for you, or try to follow the next section to compiling Lammps by yourself.

### Compiling LAMMPS yourself
In this short tutorial, we only briefly cover how to building Lammps with cmake.

#### 1. Check CMake

```bash
which cmake && cmake --version
```
**LAMMPS currently requires CMake version 3.20 or later.**

#### 2. Download the source code

```bash
wget https://github.com/lammps/lammps/releases/download/stable_22Jul2025_update3/lammps-src-22Jul2025_update3.tar.gz
```

#### 3. Unpack the source code

```bash
tar xf lammps-src-22Jul2025_update3.tar.gz
```
tree view of the source code fold after unpack:
```bash
lammps-22Jul2025/
├── bench/
├── cmake/
├── doc/
├── examples/
├── fortran/
├── lib/
├── LICENSE
├── potentials/
├── python/
├── README
├── src/
├── third_party/
├── tools/
└── unittest/
```

#### 4. Create build and installation directories

```bash
mkdir -p build lammps/22Jul2025/update3
```
looks like:
```bash
ls
build lammps lammps-22Jul2025
```

#### 5. Select LAMMPS packages

in the folder `lammps-22Jul2025/cmake/presets`, there are files:
```bash
all_off.cmake all_on.cmake basic.cmake most.cmake
```
could be use as a start point to customize your packages to install. here we chose `most.cmake` as a example, which should has switched on the most of the packages. 
```bash
cp lammps-22Jul2025/cmake/presets/most.cmake build/pkgs.cmake
```
you could edit the `pkgs.cmake` to remove or add the packages. 


#### 6. Configure and compile LAMMPS

We choose KOKKOS for GPU support, and also build the Lammps shared libs which may needed if calling/link lammps from other code.
* LUMI: AMD CPU + AMD GPU



#### LUMI-C with CPU only

```bash
module purge
module load LUMI
module load partition/C
module load PrgEnv-cray
module load cray-fftw
module load cray-python

cd build

prefix=$(dirname $(pwd))/lammps/22Jul2025/update3
cmake ../lammps-22Jul2025/cmake \
-C ./pkgs.cmake \
-DCMAKE_INSTALL_PREFIX=$prefix \
-DBUILD_SHARED_LIBS=yes \
-DBUILD_MPI=yes \
-DBUILD_OMP=yes \
-DPKG_PYTHON=ON

make VERBOSE=1 -j 16 install

```

#### LUMI-G with GPU support

```bash
module purge
module load LUMI
module load partition/G
module load PrgEnv-amd
module load cray-fftw
module load rocm
module load cray-python

export HIPCC_COMPILE_FLAGS_APPEND="--offload-arch=gfx90a $(CC --cray-print-opts=cflags)"
export HIPCC_LINK_FLAGS_APPEND=$(CC --cray-print-opts=libs)

cd build

prefix=$(dirname $(pwd))/lammps/22Jul2025/update3
cmake ../lammps-22Jul2025/cmake \
-C ./pkgs.cmake \
-DCMAKE_INSTALL_PREFIX=$prefix \
-DBUILD_SHARED_LIBS=yes \
-DBUILD_MPI=yes \
-DBUILD_OMP=yes \
-DMPI_CXX_COMPILER=$(which hipcc) \
-DCMAKE_CXX_COMPILER=$(which hipcc) \
-DCMAKE_C_COMPILER=$(which hipcc) \
-DCMAKE_Fortran_COMPILER=$(which gfortran) \
-DCMAKE_BUILD_TYPE=Release \
-DPKG_PYTHON=ON \
-DAMDGPU_TARGETS=gfx90a \
-DPKG_KOKKOS=ON \
-DKokkos_ENABLE_SERIAL=ON \
-DKokkos_ENABLE_OPENMP=ON \
-DKokkos_ENABLE_HIP=ON \
-DKokkos_ENABLE_HIP_MULTIPLE_KERNEL_INSTANTIATIONS=ON \
-DKokkos_ARCH_AMD_GFX90A=ON \
-DKokkos_ARCH_ZEN3=ON \
-DKokkos_ENABLE_DEPRECATION_WARNINGS=OFF \
-DFFT=FFTW3 \
-DFFT_KOKKOS=hipFFT

make VERBOSE=1 -j 16 install
```

#### 7. Run a LAMMPS example with Slurm
* we choose lammps-22Jul2025/bench/in.lj as example 
    ```bash
    mkdir example
    cp lammps-22Jul2025/bench/in.lj exmaple/
    ```
* creat slurm job scripts by copy one of the blow code block into a file: `job.sh`


#### LUMI-C with CPU only

```bash
#!/bin/bash -l
#SBATCH --partition=debug #choose another queue for production
#SBATCH --nodes=1
#SBATCH --ntasks-per-node=128
#SBATCH --time=00:05:00 #change longer for production case

module purge
module load LUMI
module load partition/C
module load PrgEnv-cray
module load cray-fftw
module load cray-python

lmp_path=../lammps/22Jul2025/update3
export LD_LIBRARY=$lmp_path/lib64:$LD_LIBRARY_PATH
export OMP_NUM_THREADS=1

srun $lmp_path/bin/lmp -in in.lj -v x 3 -v y 3 -v z 3

```

#### LUMI-G with GPU support

```bash
#!/bin/bash -l
#SBATCH --partition=dev-g #choose another queue for production
#SBATCH --nodes=1
#SBATCH --ntasks-per-node=8
#SBATCH --gpus-per-node=8
#SBATCH --time=00:05:00 #change longer for production case

module purge
module load LUMI
module load partition/G
module load PrgEnv-amd
module load cray-fftw
module load rocm
module load cray-python

lmp_path=../lammps/22Jul2025/update3
export LD_LIBRARY=$lmp_path/lib64:$LD_LIBRARY_PATH

export MPICH_GPU_SUPPORT_ENABLED=1
export OMP_NUM_THREADS=1
export OMP_PROC_BIND=spread
export OMP_PLACES=threads

srun ./lmp -in in.lj -k on g 8 -sf kk -pk kokkos -v x 8 -v y 8 -v z 8
```


* submit the job.sh: change the `xxxxxx` to your project number on the hpc system.
    ```bash
    sbatch -A xxxxxx job.sh
    ```
