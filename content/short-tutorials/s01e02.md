# Episode 2: LAMMPS with MACE on Leonardo Booster

Build a GPU-enabled LAMMPS executable with the ML-IAP interface, install MACE
in a Python environment, and submit a small copper simulation on Leonardo Booster.
This example uses a CUDA 12 software stack and explicit PyTorch and
cuEquivariance versions.

## Before you start

:::{prereq}
- A Leonardo Booster account and a Slurm allocation with GPU access.
- Familiarity with the installation workflow in {doc}`s01e01`.
- Access to the listed compiler, MPI, CUDA, FFTW, CMake, and Python modules,
  or suitable equivalents provided by the centre.
- A working directory with enough space for the source trees, build, environment,
  and model file.
:::

By the end of this tutorial, you should be able to build LAMMPS with Python and
GPU support, check the MACE environment, convert a model, and run a test job.

Consult {doc}`../reference/cuda_driver_cuda_cc_mapping` when comparing the
installed NVIDIA driver, CUDA toolkit, and GPU architecture. The versions below
are the ones used in this example; the cloned source repositories can change,
so record their revisions if you need to reproduce the build later.

## 1. Prepare the source and working directory

Run the setup steps in one shell session. `LAMMPS_MACE_WORKDIR` records the
project root so that later directory changes are explicit:

```bash
mkdir -p lammps-mace-work
cd lammps-mace-work
export LAMMPS_MACE_WORKDIR="$PWD"

git clone --branch develop https://github.com/lammps/lammps.git
git clone https://github.com/ACEsuit/mace.git

git -C lammps rev-parse HEAD
git -C mace rev-parse HEAD
```

The [MACE ML-IAP guide](https://mace-docs.readthedocs.io/en/latest/guide/lammps_mliap.html)
uses the LAMMPS `develop` branch and recommends activating the Python environment
before configuring LAMMPS. This tutorial follows that ordering.

As you complete the steps, the directory layout will be:

```text
lammps-mace-work/
├── lammps/              # source
├── mace/                # source
├── pkgs.cmake           # package preset
├── lammps_mace_venv/     # Python environment
├── build/               # CMake build
├── lammps-mace/          # installed executable and shared library
├── check_runtime.py     # environment check
└── test/                # model, LAMMPS input, and Slurm job script
```

## 2. Load modules and prepare Python

### Load the build environment

Run from `LAMMPS_MACE_WORKDIR`:

```bash
module purge
module load cmake/3.27.9
module load gcc/12.2.0
module load cuda/12.2
module load openmpi/4.1.6--gcc--12.2.0-cuda-12.2
module load fftw/3.3.10--openmpi--4.1.6--gcc--12.2.0-spack0.22
module load python/3.11.7
```

Keep this module environment loaded during compilation and Python package
installation. The Python interpreter used to build LAMMPS must match the
interpreter used for its Python interface.

### Create and activate the environment

```bash
cd "$LAMMPS_MACE_WORKDIR"
python -m venv lammps_mace_venv
source lammps_mace_venv/bin/activate

python --version
python -m pip --version
python -m pip install --upgrade pip setuptools wheel
python -m pip install Cython numpy
```

Check that Python reports version 3.11 and that the pip path points into
`lammps_mace_venv`. Cython and NumPy are needed for the Python-enabled build.

## 3. Compile LAMMPS

### Select the packages

The main build options are:

| Option | Purpose |
| --- | --- |
| `BUILD_MPI` | MPI parallel execution. |
| `BUILD_SHARED_LIBS` | A shared LAMMPS library for the Python interface. |
| `PKG_KOKKOS`, `Kokkos_ENABLE_CUDA` | GPU execution through KOKKOS and CUDA. |
| `PKG_PYTHON` | Python support; requires Python development headers and libraries. |
| `PKG_ML-IAP`, `MLIAP_ENABLE_PYTHON` | The Python-enabled ML-IAP interface. |
| `PKG_ML-SNAP` | An additional package enabled by this recipe. |

Save the following as `pkgs.cmake` in `LAMMPS_MACE_WORKDIR`. Add other packages
only if your simulation needs them:

```cmake
# preset that turns on just a few, frequently used packages
# this will be compiled quickly and handle a lot of common inputs.

set(ALL_PACKAGES KSPACE MANYBODY MOLECULE RIGID)

foreach(PKG ${ALL_PACKAGES})
  set(PKG_${PKG} ON CACHE BOOL "" FORCE)
endforeach()
```

### Configure, build, and install

Keep the virtual environment active. Run from `LAMMPS_MACE_WORKDIR`:

```bash
mkdir -p build
cd build
cmake ../lammps/cmake \
       -C ../pkgs.cmake \
       -DCMAKE_INSTALL_PREFIX="$LAMMPS_MACE_WORKDIR/lammps-mace" \
       -DBUILD_SHARED_LIBS=yes \
       -DBUILD_MPI=yes \
       -DPKG_PYTHON=ON \
       -DPKG_ML-IAP=ON \
       -DMLIAP_ENABLE_PYTHON=ON \
       -DPKG_ML-SNAP=ON \
       -DBUILD_OMP=yes \
       -DMPI_CXX_COMPILER=mpiCC \
       -DCMAKE_CXX_COMPILER=g++ \
       -DCMAKE_C_COMPILER=gcc \
       -DCMAKE_Fortran_COMPILER=gfortran \
       -DCMAKE_BUILD_TYPE=Release \
       -DPKG_KOKKOS=ON \
       -DKokkos_ENABLE_SERIAL=ON \
       -DKokkos_ENABLE_OPENMP=ON \
       -DKokkos_ENABLE_CUDA=ON \
       -DKokkos_ARCH_AMPERE80=ON \
       -DKokkos_ARCH_ICX=ON \
       -DKokkos_ENABLE_DEPRECATION_WARNINGS=OFF \
       -DFFT=FFTW3 \
       -DFFT_KOKKOS=CUFFT

make -j 8 install

cd "$LAMMPS_MACE_WORKDIR"
```

Check the CMake output for the selected Python interpreter, CUDA toolkit, and
MPI implementation. The installation should contain `lammps-mace/bin/lmp`
and the shared LAMMPS library.

## 4. Install the Python runtime packages

Keep the same modules loaded and `lammps_mace_venv` active. Run from
`LAMMPS_MACE_WORKDIR`.

### Install PyTorch

This example selects PyTorch 2.5.1 from its CUDA 12.1 wheel index:

```bash
python -m pip install "torch==2.5.1" --index-url "https://download.pytorch.org/whl/cu121"
```

### Install the MACE dependencies

```bash
python -m pip install \
  "e3nn==0.4.4" \
  numpy \
  opt_einsum \
  ase \
  torch-ema \
  prettytable \
  matscipy \
  h5py \
  torchmetrics \
  python-hostlist \
  configargparse \
  GitPython \
  pyYAML \
  tqdm \
  lmdb \
  orjson \
  matplotlib \
  pandas
```

### Install cuEquivariance

Use the CUDA 12 backend with the versions selected for this example:

```bash
python -m pip install --no-deps \
  "cuequivariance==0.8.1" \
  "cuequivariance-torch==0.8.1" \
  "cuequivariance-ops-torch-cu12==0.8.1"
```

### Install MACE and the LAMMPS Python interface

`--no-deps` keeps the explicitly installed packages rather than letting this
step choose another dependency stack. Check the package requirements afterward:

```bash
cd "$LAMMPS_MACE_WORKDIR/mace"
python -m pip install --no-deps .

cd "$LAMMPS_MACE_WORKDIR/build"
make install-python

cd "$LAMMPS_MACE_WORKDIR"
python -m pip check
```

If `pip check` reports missing or incompatible dependencies, resolve them before
running the simulation. Consult the MACE ML-IAP guide for the requirements of
your chosen source revision.

## 5. Verify the runtime environment

Make the executable and shared library available in the current shell:

```bash
export PATH="$LAMMPS_MACE_WORKDIR/lammps-mace/bin:$PATH"
export LD_LIBRARY_PATH="$LAMMPS_MACE_WORKDIR/lammps-mace/lib64:$LAMMPS_MACE_WORKDIR/lammps-mace/lib:${LD_LIBRARY_PATH:-}"
```

Save the following as `check_runtime.py` in `LAMMPS_MACE_WORKDIR`:

```python
import importlib.util
from importlib import metadata

import torch

for package in ["torch", "mace-torch", "cuequivariance", "cuequivariance-torch"]:
    print(f"{package} package:", metadata.version(package))

print("torch:", torch.__version__)
print("torch.version.cuda:", torch.version.cuda)
print("cuda available:", torch.cuda.is_available())
if torch.cuda.is_available():
    print("gpu:", torch.cuda.get_device_name(0))
    x = torch.ones((2, 2), device="cuda")
    print("cuda tensor sum:", x.sum().item())

for module in ["mace", "e3nn", "cuequivariance", "cuequivariance_torch", "lammps"]:
    spec = importlib.util.find_spec(module)
    print(f"{module}: {'FOUND' if spec else 'missing'}")
```

Run the check in an allocated GPU session with the modules and virtual
environment loaded:

```bash
cd "$LAMMPS_MACE_WORKDIR"
python check_runtime.py
```

Check that the listed modules are `FOUND`, CUDA is available, and the GPU tensor
sum is `4.0`. A login node without GPU access can report CUDA as unavailable;
perform the GPU check inside an allocation.

## 6. Run a test simulation

### Download and convert the model

Create and enter the test directory:

```bash
cd "$LAMMPS_MACE_WORKDIR"
mkdir -p test
cd test
wget -O mace-mp-0b3-medium.model https://huggingface.co/mace-foundations/mace-mp-0/resolve/main/mace-mp-0b3-medium.model
python ../mace/mace/cli/create_lammps_model.py mace-mp-0b3-medium.model --format=mliap
```

Keep the converted model, input file, and job script together in this directory.
The input below expects `mace-mp-0b3-medium.model-mliap_lammps.pt`.

### Create the LAMMPS input

Save the following as `in.cu_mace_mliap_kk` in `LAMMPS_MACE_WORKDIR/test`.
It creates a periodic copper system and runs 1,000 time steps:

```text
# in.cu_mace_mliap_kk

units           metal
atom_style      atomic
boundary        p p p
newton          on

lattice         fcc 3.615
region          box block 0 8 0 8 0 8
create_box      1 box
create_atoms    1 box

mass            1 63.546

pair_style      mliap unified mace-mp-0b3-medium.model-mliap_lammps.pt 0
pair_coeff      * * Cu

neighbor        2.0 bin
neigh_modify    every 1 delay 0 check yes

velocity        all create 300.0 12345 mom yes rot no dist gaussian

timestep        0.001
thermo          10
thermo_style    custom step temp pe etotal press vol

fix             1 all nvt temp 300 300 0.1

run             1000
```

### Create the Slurm job script

Save the following as `job.sbatch` in the same test directory. Before submitting:

- Replace `EUHPC_XXX_XXX` with your allocation account.
- Check that the module names match those available on Leonardo.
- Adapt the node, MPI task, CPU, and GPU counts to your allocation and workload.
- Use the debug QoS and short time limit for this test; choose appropriate
  settings for production jobs.

The script assumes you submit from `LAMMPS_MACE_WORKDIR/test`, with the
installation and virtual environment in its parent directory.

```bash
#!/bin/bash
#SBATCH -N 1
#SBATCH -n 1
#SBATCH -c 8
#SBATCH --gres=gpu:1
#SBATCH -A EUHPC_XXX_XXX
#SBATCH -t 30:00
#SBATCH -p boost_usr_prod
#SBATCH --qos=boost_qos_dbg # remove for production runs

module purge
module load cmake/3.27.9
module load gcc/12.2.0
module load cuda/12.2
module load openmpi/4.1.6--gcc--12.2.0-cuda-12.2
module load fftw/3.3.10--openmpi--4.1.6--gcc--12.2.0-spack0.22
module load python/3.11.7

export PATH="$PWD/../lammps-mace/bin:$PATH"
export LD_LIBRARY_PATH="$PWD/../lammps-mace/lib64:$PWD/../lammps-mace/lib:${LD_LIBRARY_PATH:-}"
source "$PWD/../lammps_mace_venv/bin/activate"

ldd "$(which lmp)"

srun lmp -k on g 1 -sf kk -pk kokkos newton on neigh half -in in.cu_mace_mliap_kk
```

### Submit and inspect the result

Run from the test directory:

```bash
cd "$LAMMPS_MACE_WORKDIR/test"
sbatch job.sbatch
```

Slurm should return a job ID. After the job finishes, inspect the Slurm output
and `log.lammps`. Confirm that the model loaded and the simulation reached
step 1,000 without errors. This small run checks the workflow; assess the model
and simulation settings separately for your research application.

## Completion checklist

- CMake used the intended Python, MPI, and CUDA environment.
- `pip check` reports no dependency conflicts.
- The runtime check finds the packages and can create a CUDA tensor in a GPU allocation.
- The converted model filename matches the filename in the LAMMPS input.
- The Slurm script uses your allocation and completes the test simulation.
